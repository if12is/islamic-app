# بطاقات النشر

بطاقات جاهزة للنشر — المتاجر، إنستجرام، تويتر — مبنية من **لقطات حقيقية للتطبيق**
لا من صور تُحاكيه.

```
ads/
  screens/   لقطات التطبيق نفسه، ١١٧٠×٢٥٣٢ (هاتف ٣٩٠×٨٤٤ بكثافة ٣×)
  cards/     البطاقات النهائية، ١٠٨٠×١٩٢٠
  card.html  قالب البطاقة
  build_cards.js
```

## لماذا لقطات حقيقية

الجهاز الذي يُبنى عليه لا يملك Android SDK، لكن بناء الويب هو **نفس شجرة الودجت**
التي يرسمها الهاتف. فالبطاقة تعرض ما سيثبّته الناس فعلاً، لا رسماً يشبهه.

## كيف تُعاد

```bash
flutter build web --release
python3 -m http.server 8899 --directory build/web &

# اللقطات: تحتاج puppeteer-core وGoogle Chrome
npm i puppeteer-core
OUT=ads/screens node scripts/shoot.js

# البطاقات
node ads/build_cards.js
```

### ثلاث حواجز في الطريق، لمن يعيدها

**السبلاش.** لقطة Chrome بـ`--virtual-time-budget` لا تتجاوزه أبداً: فلاتر يدور في
حلقة `requestAnimationFrame` فلا تسكن الصفحة قط، واللقطة تقع على ما هو معروض حين
تنتهي الميزانية. الحل انتظار حقيقي بالساعة عبر التحكّم بالمتصفّح.

**الأونبوردنج.** ملفّ Chrome جديد يعني تشغيلاً أولاً، فيفتح التطبيق على شاشة
الترحيب. يُزرع `is_first_launch` في `localStorage` — وهو موضع `SharedPreferences`
على الويب.

**اتجاه شريط التنقّل.** المواضع بالبكسل من اليسار، والشريط يُرسم من اليمين، فأول
وجهة في الكود تقع أقصى اليمين والترتيب بالبكسل معكوس:

```
بكسل   0        1        2        3        4
      الصلاة   القرآن   الرئيسية  الأذكار  الورد
```

قراءتها بالعكس تُخرج ثلاث بطاقات بعناوين ميزات أخرى.

## التصميم

الألوان والخطوط من `design_tokens.dart` و`assets/fonts` مباشرةً — لا نسخة ثانية
منها. البطاقة في خط **ريم كوفي** كما التطبيق، والذهبي المستعمل في الكتابة هو
`goldInk` لا `gold`، لأن الأول وحده يمرّ في التباين.

الوضع الفاتح لأنه ما يراه أكثر الناس. اللقطات تُلتقط بالضغط على مفتاح المظهر في
التطبيق نفسه، لا بزرع القيمة: ترميز `SharedPreferences` على الويب تفصيلة داخلية في
إضافة، وزرعها يدوياً تخمين، أما الضغط على الزر فهو ما يفعله المستخدم ولا يخطئ.
